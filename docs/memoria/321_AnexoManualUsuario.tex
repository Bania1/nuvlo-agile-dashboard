\section{Introducción}

Este anexo describe el uso básico de Nuvlo desde el punto de vista de un usuario final. Nuvlo es una aplicación web para consultar métricas ágiles calculadas a partir de datos de Jira Cloud, tomando como referencia la gestión de trabajo de Jira y la información disponible mediante su API REST~\cite{AtlassianJira,AtlassianJiraRestV3}. La aplicación no sustituye a Jira como herramienta de gestión de proyectos, sino que actúa como una capa de análisis para visualizar indicadores como \textit{WIP}, \textit{Velocity}, \textit{Lead Time}, \textit{Cycle Time}, alertas y registros de actividad.

El sistema ofrece dos modos de trabajo:

\begin{itemize}
    \item \textbf{Modo Jira}: utiliza autenticación OAuth con Atlassian y sincroniza datos reales desde Jira Cloud~\cite{AtlassianOAuth3LO,AtlassianJiraRestV3}.
    \item \textbf{Modo demo \textit{offline}}: utiliza un conjunto de datos local controlado para mostrar y probar el funcionamiento de la aplicación sin depender de Jira Cloud ni de la conexión de red.
\end{itemize}

\section{Instalación y puesta en marcha}

Para ejecutar Nuvlo en un entorno local se necesita tener instalado Node.js, npm y Docker. La versión recomendada para el desarrollo es Node.js 24 LTS, ya que es la utilizada durante la implementación del proyecto. Docker se emplea para levantar los servicios auxiliares de PostgreSQL y Redis.

El proceso general de instalación es el siguiente:

\begin{enumerate}
    \item Obtener el código fuente del repositorio del proyecto.
    \item Crear el fichero de configuración local a partir de la plantilla \texttt{.env.example}.
    \item Rellenar las variables de entorno necesarias, especialmente las relacionadas con PostgreSQL, Redis, seguridad de sesión y OAuth de Atlassian.
    \item Instalar las dependencias de Node.js mediante \texttt{npm install}.
    \item Levantar PostgreSQL y Redis con \texttt{docker compose up -d}.
    \item Generar el cliente de Prisma con \texttt{npm run db:generate}.
    \item Preparar los datos de demostración con \texttt{npm run demo:data}.
    \item Aplicar el esquema de base de datos con \texttt{npm run db:push}.
    \item Cargar los datos iniciales con \texttt{npm run db:seed}.
    \item Arrancar la aplicación con \texttt{npm run dev}.
\end{enumerate}

Una vez iniciada, la interfaz web queda disponible en \texttt{http://localhost:5174} y la API en \texttt{http://localhost:3002}. Si el puerto del cliente estuviera ocupado, Vite puede seleccionar automáticamente el siguiente puerto disponible; en ese caso se debe utilizar la URL indicada por la terminal.

\section{\textit{Dashboard} principal}

Tras iniciar sesión o acceder al modo demo, Nuvlo muestra el \textit{dashboard} principal (Figura~\ref{fig:manual-dashboard-jira}). Esta vista resume el estado del proyecto seleccionado e incluye tarjetas de métricas, gráficos, avisos y una lista de incidencias recientes.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth,trim=0 420bp 0 0,clip]{img/app-jira/01-dashboard-jira.png}
    \caption{\textit{Dashboard} principal con datos sincronizados desde Jira}
    \label{fig:manual-dashboard-jira}
\end{figure}

Las tarjetas superiores muestran:

\begin{itemize}
    \item \textbf{\textit{Lead Time}}: tiempo desde la creación de una incidencia hasta su finalización, métrica habitual para analizar el flujo de entrega~\cite{Anderson2010Kanban}.
    \item \textbf{\textit{Cycle Time}}: tiempo desde que una incidencia entra en trabajo activo hasta que se finaliza.
    \item \textbf{\textit{WIP}}: trabajo en curso visible según los filtros aplicados.
    \item \textbf{\textit{Velocity}}: trabajo completado, usando puntos de historia cuando Jira los proporciona o número de incidencias como alternativa, en línea con la planificación iterativa descrita en Scrum~\cite{ScrumGuide2020}.
\end{itemize}

En proyectos reales creados para demostración, algunas métricas temporales pueden aparecer con valores muy bajos o nulos si las transiciones de Jira se han producido en un intervalo corto. Para validar cálculos temporales históricos se utiliza el \textit{dataset} \textit{offline} controlado del apartado~\ref{sec:manual-demo-offline}.

\section{Sincronización con Jira}

Cuando hay una sesión OAuth activa, el botón \textit{Sincronizar Jira}, visible en el \textit{dashboard} de la Figura~\ref{fig:manual-dashboard-jira}, actualiza los datos del proyecto seleccionado. La aplicación solicita los datos necesarios a Jira Cloud, incluidos datos de incidencias y cambios de estado cuando están disponibles~\cite{AtlassianJiraIssuesApi}, los almacena en PostgreSQL y recalcula el \textit{dashboard} desde la base de datos local. Este diseño reduce llamadas repetidas a Jira y permite consultar la información aunque la API externa no se llame en cada interacción de la interfaz.

\section{Configuración}

La vista de configuración resume el estado de conexión con Jira, los proyectos visibles y la información asociada a la sesión (Figura~\ref{fig:manual-configuracion-jira}). También permite ajustar y guardar la configuración de análisis del proyecto: estados que representan trabajo iniciado, estados finales, tipos de incidencia, etiquetas, rango temporal y percentiles utilizados. Al guardar estos criterios, el \textit{dashboard} se recalcula con el nuevo ámbito. Si el usuario desea volver al comportamiento inicial, puede restaurar los valores por defecto y guardarlos de nuevo desde la misma vista. Además, la vista ofrece una forma clara de volver a conectar Jira si la sesión caduca o si el usuario quiere renovar permisos.

\section{Demo \textit{offline}}\label{sec:manual-demo-offline}

La demo \textit{offline} se utiliza para mostrar el comportamiento de la aplicación con un conjunto de datos controlado (Figura~\ref{fig:manual-demo-offline-dashboard}). Su objetivo principal es permitir pruebas y demostraciones aunque Jira Cloud no esté disponible, aunque la cuenta de Atlassian no esté configurada o aunque el proyecto real no tenga suficiente histórico para calcular métricas temporales representativas.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=\textwidth,trim=0 420bp 0 0,clip]{img/app-demo/02-dashboard-principal.png}
    \caption{Pantalla principal al acceder a la demo \textit{offline}}
    \label{fig:manual-demo-offline-dashboard}
\end{figure}

En este modo se mantienen las mismas vistas principales de la aplicación: \textit{dashboard}, filtros, tablero, alertas, actividad, configuración y vista móvil. La diferencia es el origen de los datos: en lugar de sincronizar información desde Jira Cloud, Nuvlo carga un \textit{dataset} local preparado para contener incidencias, estados, \textit{sprints}, tiempos de flujo y alertas de ejemplo.

La demo \textit{offline} puede estar disponible antes de iniciar sesión, desde la pantalla de entrada. Esto se plantea como una opción de demostración y validación, no como acceso a datos reales de una organización. Los datos mostrados son ficticios y no contienen información privada ni proceden de Jira Cloud. Por tanto, un usuario puede explorar la interfaz y las funcionalidades visuales sin autorizar su cuenta Atlassian, pero para trabajar con proyectos reales necesita usar \textit{Conectar con Jira}.

A diferencia de Jira real, este \textit{dataset} sí contiene valores temporales preparados para comprobar que los cálculos de \textit{Lead Time}, \textit{Cycle Time}, percentiles, \textit{WIP} y \textit{Velocity} se visualizan correctamente. Las funcionalidades se comportan igual desde el punto de vista de interacción, pero los resultados no deben interpretarse como métricas reales de un equipo.
