\chapter{Uso de herramientas de inteligencia artificial}\label{uso-ia}
Durante la elaboración de este Trabajo de Fin de Grado se han utilizado herramientas de inteligencia artificial generativa como apoyo auxiliar. Su uso se ha orientado a mejorar el proceso de desarrollo y documentación, pero sin sustituir el criterio técnico del autor ni la revisión final de los contenidos incorporados a la memoria y al código fuente.

\section{Objetivo del uso}

El objetivo principal ha sido utilizar la IA como una herramienta de apoyo durante el trabajo diario: ordenar ideas, revisar textos, contrastar decisiones técnicas, detectar posibles incoherencias y acelerar tareas repetitivas. En ningún caso se ha utilizado como fuente primaria de información académica o técnica. Las explicaciones, requisitos, decisiones de diseño y resultados finales han sido revisados y adaptados antes de formar parte del proyecto.

\section{Tareas realizadas con apoyo de IA}

Las herramientas de inteligencia artificial se han utilizado principalmente en las siguientes tareas:

\begin{itemize}
    \item Revisión y mejora de fragmentos de texto de la memoria, procurando que la redacción fuese clara y coherente.
    \item Organización de secciones, anexos, manual de usuario, manual técnico y matriz de validación de requisitos.
    \item Comprobación de coherencia entre requisitos, casos de uso, diagramas, capturas y funcionamiento real de la aplicación.
    \item Apoyo en la planificación incremental del desarrollo, especialmente para dividir el trabajo en fases y commits manejables.
    \item Revisión de errores durante la ejecución local, instalación de dependencias, configuración de Docker, PostgreSQL, Redis y entorno de desarrollo.
    \item Apoyo en la implementación y revisión de partes del código, incluyendo autenticación OAuth con Atlassian, sincronización con Jira Cloud, cálculo de métricas, alertas, logs, pruebas y generación de capturas.
    \item Preparación de scripts auxiliares para demo offline, generación de datos controlados y validación de capturas reproducibles.
\end{itemize}

\section{Uso durante la implementación}

La IA también se ha utilizado como asistente de programación para proponer cambios, revisar fragmentos de código y ayudar a localizar errores. Las propuestas generadas se han contrastado con el comportamiento esperado de la aplicación y con las pruebas disponibles antes de incorporarse al repositorio.

En particular, se empleó apoyo de IA en las siguientes áreas de la implementación:

\begin{itemize}
    \item Estructuración del monorepo con aplicaciones separadas para frontend y backend.
    \item Desarrollo de la interfaz web de Nuvlo y adaptación visual a las vistas previstas en los prototipos.
    \item Configuración de autenticación con Atlassian mediante OAuth 2.0 3LO, incluyendo estado de sesión, CSRF, PKCE y uso de cookies \texttt{httpOnly}, tomando como referencia documentación oficial y recomendaciones de seguridad web~\cite{AtlassianOAuth3LO,OWASPOAuth2,OWASPCSRF}.
    \item Integración con Jira Cloud API para sincronizar proyectos, incidencias, sprints y changelog~\cite{AtlassianJiraRestV3,AtlassianJiraIssuesApi}.
    \item Persistencia en PostgreSQL y uso de Redis para datos temporales y cachés con tiempo de vida limitado~\cite{PostgreSQLDocs,RedisDocs}.
    \item Implementación de métricas ágiles como WIP, Velocity, Lead Time, Cycle Time, percentiles y Throughput.
    \item Creación de alertas por umbral, notificaciones visuales, historial de alertas y registro de actividad.
    \item Elaboración de pruebas unitarias, de integración y E2E para validar partes críticas del sistema~\cite{VitestGuide,PlaywrightDocs}.
\end{itemize}

\section{Uso de integraciones y herramientas conectadas}

Durante el desarrollo se utilizaron integraciones de la herramienta de IA con servicios relacionados con el proyecto. Entre ellas destacan el acceso al repositorio Git para revisar el estado de cambios, preparar commits y comprobar el historial, así como el uso de conectores con Atlassian/Jira para contrastar información del proyecto y validar el funcionamiento de la integración.

También se emplearon capacidades de trabajo sobre el entorno local para ejecutar comandos, revisar logs, comprobar servicios en Docker, validar pruebas y generar capturas de pantalla destinadas a la documentación. Este uso permitió detectar errores de configuración, como conflictos de puertos, versiones de Node.js, problemas de autenticación OAuth o ficheros que no debían formar parte del repositorio remoto.

\section{Fuentes externas y código reutilizado}

Cuando se ha necesitado información técnica externa, se han consultado fuentes documentales específicas, como la documentación oficial de Atlassian para OAuth 2.0 3LO y Jira REST API~\cite{AtlassianOAuth3LO,AtlassianJiraRestV3}, la documentación de las herramientas utilizadas en el stack y las referencias de las librerías empleadas~\cite{ReactDocs,ViteDocs,NodeDocs,ExpressDocs,PrismaDocs,DockerComposeDocs}. Estas fuentes se han usado para comprender APIs, parámetros de configuración, buenas prácticas y restricciones técnicas.

No se han incorporado ficheros completos de código fuente externo como parte propia del proyecto. La aplicación utiliza dependencias de código abierto instaladas mediante los gestores habituales del ecosistema JavaScript, como React, Vite, Express, Prisma, Vitest, Playwright y otras librerías auxiliares. En el diseño visual del dashboard se consultó como inspiración una plantilla moderna de administración de Morphin~\cite{MorphinDashboardInspiration}; esta referencia se usó para orientar criterios generales de composición, tarjetas, navegación lateral y aspecto de dashboard, sin copiar su código fuente ni reproducirla literalmente.

\section{Supervisión y responsabilidad}

Todo el contenido finalmente incorporado al trabajo ha sido revisado, corregido y adaptado antes de su inclusión. Las decisiones sobre alcance, requisitos, diseño, arquitectura, selección de tecnologías, redacción final y validación del sistema corresponden al autor del trabajo.

Por tanto, el uso de IA debe entenderse como apoyo al proceso de elaboración: ayuda a ordenar, revisar, probar y documentar, pero no reemplaza la toma de decisiones, la comprensión técnica ni la responsabilidad sobre el resultado final.
